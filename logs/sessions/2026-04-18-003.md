## Decisions Made

- **HistoryScreen layout**: Flat list with border-bottom dividers (not cards). Matches mockup. Each row has fixed 38dp date column (Bebas Neue day number + abbreviated day name), weight in Bebas Neue 22sp, today row with accent-dim background.
- **Delta chip shape**: 6dp radius (rectangular) per mockup — not pill-shaped (20dp) as initially implemented.
- **Same-delta state**: Gray chip for zero-change entries (mockup `.hi-d.same`), handled via `DeltaChip` composable with null/isDown branching.
- **ProfileViewModel deps**: Extended to take `WeightRepository` + `BadgeObserver`. Goal progress, streak, BMI, and summary all computed in VM — keeps ProfileScreen pure display.
- **Settings not wired**: Settings files only exist in `.worktrees/phase3/` (PR #30 not merged). No Settings nav button added to ProfileScreen.
- **Badge display**: All 12 `Badge` enum values shown in `LazyRow`; earned = accent-dim background + accent border; locked = opacity via WFTokens.Card + border. Emoji + short name mapping defined in ProfileScreen.

## Reasoning

Mockup comparison revealed the initial HistoryScreen implementation used card-per-entry layout while the mockup uses a flat list with dividers — a significant visual difference. The date column (Bebas Neue day number) is the most distinctive element of the History screen and was missing entirely in the first pass. Always compare against the mockup before declaring a screen done.

ProfileViewModel was intentionally kept thin in Phase 2 (only profile + unit). Phase 3 adds BadgeObserver (RFC #24 pattern) and WeightRepository to surface earnedBadges, streak, goal progress, and BMI. Keeping all computation in the VM means the screen is pure display — no business logic in composables.
