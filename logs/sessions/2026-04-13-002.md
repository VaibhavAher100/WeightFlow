## Decisions Made

- **Google Fonts via `ui-text-google-fonts`** — chosen over bundled TTF files (can't download binaries in session) and over `FontFamily.Default` stubs. Font certs XML must be created manually when the library doesn't auto-bundle them.
- **`font_certs.xml` manually created** — the `ui-text-google-fonts` AAR did not expose `R.array.com_google_android_gms_fonts_certs` in this build. Created the resource file explicitly. This is a known pattern in some Gradle/AGP configurations.
- **Placeholder `PlaceholderScreen` composables in NavGraph** — Phase 2 will replace them; stub keeps Phase 1 buildable and launchable without any screen code.
- **FAB only on Home tab** — `onHomeTab` check in `ShellScreen` hides FAB on Trends/History/Profile. Matches product decision (no Log tab).
- **`enableEdgeToEdge()`** in MainActivity — correct for AGP 9.x / API 26+ target.

## Reasoning

Steps 10+11 have no unit tests (visual/navigation verification only). The theme system is fully wired to DataStore — palette string flows from `UserPrefsDataStore.themePalette` → `MainActivity` → `WeightFlowTheme` → `MaterialTheme`. The NavGraph shell gives a buildable, launchable app with correct navigation structure that Phase 2 screen implementations will slot into.

The `font_certs.xml` workaround is well-documented in the Android community. Google Fonts work at runtime via the downloadable fonts mechanism — the cert file only authenticates the GMS fonts provider, not individual fonts. If a font fails to load (e.g. no network on first launch), Compose falls back to system fonts gracefully.
