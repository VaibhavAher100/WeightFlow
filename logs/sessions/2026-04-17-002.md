## Decisions Made

**Device-transfer kept enabled until export ships:** Disabling it before a user-facing export/import or Firebase sync path exists causes avoidable data loss on phone replacement. Re-enable block only when Phase 5 Firebase sync or in-app CSV export UI is shipped.

**`isMinifyEnabled = false` deferred:** Enabling R8 without ProGuard rules risks breaking Room + Kotlin serialization in release. Phase 4 item — needs rules written first.

**Vico 1.13.1 stay locked:** 3.1.0 available but requires full API rewrite of TrendsScreen. Upgrade decision deferred to Phase 3 brainstorm.

## Reasoning

**Why remove Crashlytics entirely instead of keeping as placeholder:** Silent error swallowing on misconfiguration makes observability worse than having nothing. A half-wired telemetry system gives false confidence. Phase 3 adds it properly with `google-services.json`.

**Why re-enable device-transfer:** The "data stays on device" promise applies to cloud sync, not local device migration. Disabling device-transfer without a backup path is a user-hostile policy change that contradicts the app's free/user-first positioning.

**Why clean the libs.versions.toml library entries:** Dead catalog entries are misleading — future Claude sessions see `firebase-bom` in libraries and assume Firebase is an active dependency. Version declarations stay (needed when Phase 3 wires it) but the library aliases are gone.
