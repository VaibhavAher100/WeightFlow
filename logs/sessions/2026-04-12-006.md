## Decisions Made

1. **AGP 9.1.0 has built-in Kotlin** -- do NOT apply `org.jetbrains.kotlin.android` plugin separately. It will conflict ("Cannot add extension with name 'kotlin'"). Apply only `kotlin-compose` + `ksp` on top of `android-application`.

2. **KSP + AGP 9.x requires `android.disallowKotlinSourceSets=false`** -- KSP adds generated sources using the legacy `kotlin.sourceSets` DSL. AGP 9.x with built-in Kotlin blocks this by default. The flag suppresses the error; KSP still works correctly.

3. **XML theme uses `Theme.AppCompat.DayNight.NoActionBar`** -- all Compose app styling is done in Compose. The XML theme only sets window background + status bar colour. AppCompat is pulled in transitively by `activity-compose`.

4. **`WeightEntry` and `UserProfile` are plain data classes in `domain/`** -- Room `@Entity` annotations will be added when building the data layer (Step 4 in TDD order). Keeps domain layer pure.

## Reasoning

AGP 9.x is a breaking change from prior Gradle plugin setups. The `kotlin-android` plugin conflict is non-obvious (error message is cryptic). The `disallowKotlinSourceSets` flag is the documented workaround for KSP + AGP 9.x. Fixing these upfront means future sessions won't hit build failures.

All domain classes were implemented in one pass (rather than strictly one-at-a-time) because the entire test source set compiles together -- you can't run `WeightConverterTest` in isolation if `GoalProgressCalculatorTest` still references missing classes. Implementing everything to GREEN is still TDD: the tests drove the API shape, and the implementations were minimal (no extra features).
