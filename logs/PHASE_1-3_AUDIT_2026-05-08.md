## Security Audit Results

### ✅ Passing Controls
1. **Database encryption** — SQLCipher 4 with Android Keystore (AES-256-CBC)
   - Existing DBs auto-migrate to encrypted on first upgrade
   - Key generation on first app launch
   - No plaintext fallback

2. **CSV export security** — 3 formats with clear threat models
   - Plaintext: marked unsafe, warns user
   - Encrypted ZIP: AES-256, password CharArray properly zeroed (BUG FIXED today)
   - Minimal CSV: quasi-identifying warning, no profile/goal data

3. **Network hardening** — No INTERNET permission
   - `network_security_config.xml` blocks cleartext traffic
   - No certificate pinning (not needed; no remote endpoints)

4. **Supply chain hardening** — GitHub Actions + Dependabot
   - All Actions pinned to commit SHAs (not mutable tags)
   - Dependency review on every PR (blocks new CVEs)
   - OSV Scanner + CodeQL SAST enabled

5. **Local-first architecture**
   - All data on-device, no cloud sync
   - Auto-backup disabled for sensitive data
   - Factory reset removes all app data

6. **Permissions** — minimal set
   - `POST_NOTIFICATIONS` (requested in-context)
   - `VIBRATE`
   - No location, camera, contacts, microphone, INTERNET

### ⚠️ Known Limitations (Accepted Risk)
1. **DataStore not encrypted** — stores non-sensitive settings (theme, unit, reminder toggle)
   - Future hardening can add DataStore encryption if threat model escalates
   
2. **ZIP central directory visible** — filename + size visible without password
   - Content encrypted, metadata structural limitation
   - Documented in UI

3. **CSV import parser** — replaced naive `.split(",")` with kotlin-csv RFC-4180
   - 5 MB file size limit, 10,000 row limit enforced
   - Malformed files may not be 100% graceful

## Security Bugs Fixed Today

### Bug #1: Password CharArray Not Being Zeroed (CsvExporter)
**Severity:** Medium (sensitive data handling)
**Symptom:** Tests failing:
  - `password shorter than 12 chars is zeroed even on rejection`
  - `password CharArray is zeroed after successful encryption`

**Root cause:** `zip4j`'s `ZipFile` constructor may interfere with the password CharArray if we pass the original. Finally block attempted to zero, but interference caused test failures.

**Fix:** Create a copy of the password before passing to zip4j, so we control the original array's lifecycle:
```kotlin
val passwordCopy = password.copyOf()  // Pass to zip4j
ZipFile(zipFile, passwordCopy).use { ... }  // zip4j works on copy
// Finally block zeroes original + copy
finally {
    passwordCopy.fill(' ')
    password.fill(' ')
}
```

**Verification:** Tests now GREEN. No regressions. ✅
